# note 貼り付け用 HTML の生成

Markdown の記事 1 本を、note の投稿画面へそのまま貼れる HTML に変換する。

## Critical: note のエディタ制約

note は貼り付けられた HTML の**構造だけ**を取り込み、CSS は捨てる。保持されるタグは限られており、
非対応の記法は貼った瞬間に崩れる。以下はスクリプトが自動処理するが、**何が起きたかを必ずユーザーに報告する**。

| Markdown | note での扱い | スクリプトの処理 |
|---|---|---|
| `#`（h1） | タイトル欄が別にある | 本文から除外し、タイトル欄用として別枠に出す |
| `##` `###` | 大見出し・小見出し | そのまま |
| `####` 以下 | **非対応** | h3 に降格して警告 |
| 表 | **非対応**（エディタに表機能が無い） | 箇条書きに変換して警告 |
| 画像 | 手動アップロードが必要 | プレースホルダを置いて警告 |
| インラインコード | 文中コードは保持されない | 素のテキストに戻して警告 |
| コードブロック | 限定的 | `<pre>` で出力して警告 |
| 太字・引用・箇条書き・番号リスト・区切り線・リンク | 保持される | そのまま |

**埋め込みカードは HTML ペーストでは作れない。** URL 単独行を貼っても文中リンクになる。
カードにしたい箇所は、貼り付け後に note 上で URL を入力し直す必要がある（この注意は出力 HTML にも入る）。

**ハッシュタグを本文に書かない。** note は公開設定で登録したタグを記事末に自動表示するため、
本文にも書くと二重になる。タグはタイトルと同様、本文の外に出す。

## ワークフロー

### 1. 記事を読む

変換対象の .md を読む。目的は 2 つ。

- ハッシュタグを選ぶための内容把握
- 表・画像・コードなど、変換で崩れる要素が含まれるかの事前確認

### 2. ハッシュタグを選ぶ

note の上限は **10 個**。次の配分を目安に、記事から具体的に選ぶ（後述の「ハッシュタグの選び方」）。
迷ったら差し替え候補も 3〜6 個用意し、`--alt-tags` で渡す。

### 3. スクリプトを実行する

```bash
python scripts/md_to_note_html.py <入力.md> \
  --tags "#タグA #タグB ..." \
  --alt-tags "#候補1 #候補2"
```

主なオプション:

| オプション | 用途 |
|---|---|
| `-o, --output` | 出力先。既定は入力と同じ場所の `.html` |
| `--title` | タイトルを上書き。既定は本文の h1 |
| `--tags` | ハッシュタグ（スペース区切り、`#` は省略可） |
| `--alt-tags` | 差し替え候補のタグ |
| `--no-merge-ref-urls` | 出典行の自動リンク化を無効にする |

**出典行の自動リンク化**: 箇条書きの項目の次行が裸 URL だけの場合、その項目をリンクに畳む。
末尾の `（2025年3月）` のような括弧書きはリンクの外に残す。畳んだ項目は毎回警告に出るので確認すること。

### 4. 出力とレポートを確認して報告する

スクリプトは標準出力に「タイトル／タグ／本文のタグ構成／要確認リスト」を出す。

- `!! note 非対応タグが残っています` が出たら、**元の .md を直してから再実行する**（HTML を手で直さない）
- 表が箇条書きになった場合は、変換結果を読んで不自然なら .md 側を箇条書きに書き直す
- ユーザーへの報告には、変換で失われたもの（表・画像・コード）を必ず含める

## ハッシュタグの選び方

**記事の内容から選ぶ。汎用タグだけで 10 個埋めない。** 配分の目安:

| 層 | 個数 | 性質 |
|---|---|---|
| 母数の大きい一般タグ | 3〜4 | 検索流入を取る。例: `#AI` `#生成AI` `#ChatGPT` |
| テーマに直結する専門タグ | 3〜4 | 濃い読者に届く。記事で扱った固有名詞から取る |
| 読者の属性・用途 | 1〜2 | 例: `#AI活用` `#DX` `#エンジニア` |
| 書き手の立ち位置 | 1 | 資格・職種・連載名など。同業からの反応を取る |

- **記事に出てくる固有名詞をタグにする**のが最も効く（企業名・製品名・技術名）
- 検索されないほどニッチなタグは、1〜2 個までに留める
- note の**公式お題タグ**は時期で変わる。推測で入れず、「投稿画面で当日のお題を確認して枠が余っていれば追加」とユーザーに伝える

## 出力 HTML の構成

生成される HTML は 1 ファイルで完結し、ブラウザで開いて使う。

- **上部パネル**（コピー対象外）: タイトル欄用テキスト、タグのチップ（クリックで 1 個ずつコピー）、コピーボタン
- **注意書き**: 貼り付け後に確認すべきこと
- **`#article`**（コピー対象）: 記事本文。`style` 属性を一切持たず、note 保持タグのみ

コピーは `text/html` でクリップボードに入るため、見出し・太字・引用・箇条書き・リンクの構造が note の書式に変換される。
クリップボード API が使えない環境（`file://` で拒否される場合がある）では自動的に範囲選択＋`execCommand` に切り替わる。

## 他スキルとの組み合わせ

- **記事の推敲は `japanese-longform-writing`** で先に済ませる。本スキルは書き上がった記事の書き出し専用で、文章には手を入れない
- **文字数の確認は `docx-word-count`**。MD 記法を除いた本文文字数が出る

## Troubleshooting

| 症状 | 原因と対処 |
|---|---|
| タイトルがファイル名になる | 本文に h1 が無い。`--title` で指定するか .md に `# ` を足す |
| 表がうまく箇条書きにならない | 3 列以上の表は機械的な変換になる。.md 側を箇条書きに書き直すのが確実 |
| 貼り付けたら書式が消えた | プレーンテキストで貼られている。note 側で「Ctrl+V」（Ctrl+Shift+V ではない）を使う |
| コピーボタンが反応しない | ブラウザがローカルファイルのクリップボード API を拒否している。範囲が選択されるので Ctrl+C を押す |
| 見出しが本文と同じ見た目で入る | note 側で見出しに変換されていない。貼り付け後に該当行を選んで見出しを指定し直す |
