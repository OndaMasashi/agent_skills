# lite-movie-creator

## 最初に必ずやること

1. `C:\work\lite-movie-creator` があることを確かめ、その `CLAUDE.md`（常に守る約束）を読む。無ければ止めてユーザーに伝える
2. 作業とコマンドの実行はすべてこのプロジェクトの中で行う。必要になったときに読む:
   - コマンドと共通部品、点検の項目: `docs/engine.md`
   - ジャンルごとの技術の選び方と費用: `docs/genres.md`
   - 方針（誰のため・どこまで作るか・迷ったときの優先順位）: `CONCEPT.md`
3. 過去の作品の `works/*/brief.md` は、企画と絵コンテの書き方の見本になる

## 原則

- ユーザーへの確認は **企画（確認1）と絵コンテ（確認2）の2回だけ**。欠けている情報は質問せず、企画案で仮に埋めて確認1で示す
- 生成 AI（画像・音楽・動画）の費用は企画で見積もり、承認を得てから使う。無料枠は無い
- 教材・解説は演出より内容の正確さを優先し、出典を `brief.md` に残す
- 共通部品（`engine/`）は2作品目で必要になったものだけ増やす。増やしたら全作品で出力照合を通す

## 流れ

### 1. 依頼を読み取り、作品名を決める

題材・目的・見る人・尺・画面の向きを読み取る。作品名（slug）は英小文字・数字・ハイフンで、`works/` の既存の名前と重ならないものにする。

### 2. 企画 → 確認1

1. `docs/genres.md` から近いジャンルの定石を選び、テイスト（絵柄・配色・フォント・音）と技術（コード描画・AI 画像・AI 音楽・声・AI 動画）を決める
2. 費用を見積もる。作り直しの分として、生成する数の 1.5 倍で計算する（例: 画像 6 枚 × 1.5 × 0.101 ドル ＋ 曲 2 本 × 0.04 ドル ＋ 声）。単価は `docs/genres.md` の表を使う
3. AskUserQuestion で確認する
   - 質問文に、なぜ今聞くのかと企画の要約（目的・尺・向き・テイスト・技術・費用）を入れる
   - 選択肢は「この企画で進める（推奨）」と、代わりの案を2つ（例: テイスト違い、費用を抑える案）。各案の description に、何が変わるかと費用を書く
4. 承認されたら `node tools/new-work.mjs <作品名> --title "題名"` で雛形を作り、`brief.md` の企画の表を埋める

### 3. 台本と絵コンテ → 確認2

1. `story.json` に台本を書く。場面 → 文、話し手ごとの演技指示（`styles`）。読み聞かせ調なら1秒あたり約 4.5 字（1本目の実測）で尺を見積もる
2. `brief.md` の絵コンテ表に、場面ごとの台詞・絵と動き・素材（AI で作るなら指示の要点）を書く
3. AskUserQuestion で確認する。質問文に場面数・見込みの尺・見せ場を要約し、全文は `brief.md` のパスで示す。選択肢は「この台本と絵コンテで作る（推奨）」「台詞を直す」「場面の構成を変える」
4. **ここから先は、下の「止める条件」に当たらない限り、最後まで止まらずに作る**

### 4. 素材を作る

- 声: `uv run --script tools/tts.py <作品名>`。1秒あたりの字数が 3〜6 字から外れる文は、読み間違いか間の取り方がおかしいので聞き直す（台詞を変えて、その文だけ作り直す）
- AI 画像: `story.json` の `images` に指示を書き、`uv run --script tools/image.py <作品名> --yes`（`--yes` は確認1で費用の承認を得たときだけ付ける。付けないと件数と費用の目安を表示して止まる）。商品や人物の見た目をそろえるときは、先に基準画像を1枚作り、各画像の `refs` に指定する
- AI の曲: `story.json` の `music` に指示を書き、`uv run --script tools/music.py <作品名> --yes`。歌を入れないときは「Instrumental only, no vocals.」と書く
- AI 動画（Veo）は道具がまだ無い。使う企画になったら `docs/genres.md` の API で作品の `scripts/` に作る
- 生成した画像は Read で目で確かめてから場面に使う。使った指示は `brief.md` の「AI 生成物の使用箇所」に記録する
- 文の途中の語に演出を合わせるときは、無音区間を測って秒数を定数にする（`docs/engine.md` の「場面の作り方の要点」）

### 5. 場面を作る

- 雛形の `src/Main.tsx` の `SCENE_VIEWS` に場面を登録し、場面の絵は `src/scenes/` に作る
- 共通部品（`Stage`・`makeAnim`・`Se`・`Voice`・`Captions` など）は `src/engine.ts` から読む
- 他の作品の部品を使いたいときは、この作品にコピーして使う（2作品目で使うものは、engine へ上げるかを検討する）
- `npm run typecheck` を通す

### 6. 試し書き出しで点検する

1. `node tools/render.mjs <作品名> --preview` を実行し、`out/preview-sheet.png` を Read で見る
2. `docs/engine.md` の「試し書き出しで点検すること」を全項目確かめる。気になるコマは ffmpeg で抜き出して拡大して見る
3. 直したら試し書き出しをやり直す。3回直しても残る問題は、報告に書いて先へ進む
4. 見つけたことと直したことを `brief.md` の「点検の記録」に書く

### 7. 本番の書き出し

`node tools/render.mjs <作品名> --loudness -16` をバックグラウンドで実行する（1920×1080・2分で約 25 分、20 秒の CM で約 4 分）。`--loudness` は書き出した後に音量をそろえる。終わったら表示されるラウドネス（-16 LUFS 前後）と最大音量（-1 dB 未満）を確かめる。

### 8. 記録して報告する

- `brief.md` の実績（長さ・費用・書き出しの所要時間）を埋める
- 報告には、完成動画のパス・長さ・費用・点検で確かめたこと・確かめられていないことを書く。最終判定はユーザーの視聴であることを明記する
- `engine/` や `tools/` を変えた場合だけ、プロジェクトの `improvement_list/` と `ROADMAP.md` を更新する

## 止める条件（確認2のあとでも止めてユーザーに聞く）

- 見積もりを超える費用が要る（作り直しが増えたなど）
- API の失敗（課金・権限・提供終了）で素材が作れない
- `engine/` の変更で、既存作品の出力照合（`tools/golden.mjs <作品名> check`）が通らない
- 教材の内容の事実関係に確信が持てない

## 既存作品を直すとき

1. その作品の `brief.md` と `story.json` を読んでから直す
2. 声は作り直さない。`tts.py <作品名> --offline` で、作り直しが要る文が無いことを確かめる。台詞を変えるときはその文だけ作り直し、その文に合わせた演出の秒数を測り直す
3. 直したら 6（試し書き出しの点検）→ 7（本番の書き出し）
