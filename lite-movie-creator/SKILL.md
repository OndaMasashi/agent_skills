# lite-movie-creator

## 最初に必ずやること

1. `C:\work\lite-movie-creator` があることを確かめ、その `CLAUDE.md`（常に守る約束）を読む。無ければ止めてユーザーに伝える
2. 作業とコマンドの実行はすべてこのプロジェクトの中で行う。必要になったときに読む:
   - コマンドと共通部品、点検の項目: `docs/engine.md`
   - ジャンルごとの技術の選び方と費用: `docs/genres.md`
   - 演出の見本帳（自作の手と本人の反応・外部の技法・Remotion の部品）: `docs/catalog/README.md`
   - 方針（誰のため・どこまで作るか・迷ったときの優先順位）: `CONCEPT.md`
3. 過去の作品の `works/*/brief.md` は、企画と絵コンテの書き方の見本になる

## 原則

- ユーザーへの確認は **企画（確認1）の1回だけ**。欠けている情報は質問せず、企画案で仮に埋めて確認1で示す。ほかに本人に聞くのは、見積もりを超える課金・git への登録・最後の視聴だけ
- **絵コンテと途中の判定は、監督役（下の節）の OK で進める**。案は担当（脚本・構成・演出・字幕・文字・エフェクト・つなぎ）に広げさせ、決めるのは監督役。担当は本人に言われなくても局面ごとに立て、束ねるのは監督役（下の「担当」の節）。自分の点検（崩れ・同期・数値）と演出の判定を分ける。自分で作ったものを自分で判定すると演出の弱さに気づけない（12本目の初版の計画は、最大の音に最大の絵が無いまま自分の点検を通っていた）
- **演出の物差しは感動**（MV は特に）。平凡・中庸に流さず、インパクトと対比（静と動・暗と明・小と大・無音と音・余白と密）で山を立てる。担当の案と監督役の判定は「無難か・決まりに触れないか」で止めず、「どの秒で、何の対比で心が動くか」で比べる。削る判断も「山の前の静けさを作るため」のように感動への効き目で理由を書く（本人の言葉 2026-10-10:「平凡や中庸ではなくＭＶはいかに感動を与えるか、そのための『インパクト』や静から動などへのコントラストなどが重要…演出家に問われる素養であり、スキルとしても重視してもらいたい」）
- **判定の第一の評価軸は「感動するか」**。演出に関わる判定（計画・素材・粗い通し・見せ場・通し・本番の前）と担当の評価では、山場ごとに「**ここで心が動くか**（動く／動かない・どの秒の何の対比で・動かないならなぜ）」を**合否と点検より先に**書かせる。崩れ・決まり・数字・読めるかの点検はその後に回し、点検が通っても心が動かない山は「直す」に入れる。心が動くかは音と動きで決まるので、山場は当たりの前後を 1 コマずつのコマ列と伴奏の音量の曲線で渡し、静止したコマだけで判定したときはその限界を判定に書かせる。いちばん確かな答えは本人の視聴なので、試し書き出しを作ったら報告にパスを書き、見るかは本人に任せる（14本目の粗い通しは物差しを指示に入れても判定の中身が守りの点検に寄り、誰も 1 倍の動画を音つきで見ていなかった。本人の言葉 2026-10-11:「mvなので『感動するか』という評価基準で評価されているか？」）
- **感動は予測できない意外性から生まれる。エキセントリック（人が思いつかない演出）を、構成・演出・エフェクトの段で組み入れる**（MV は特に）。脚本そのものを奇抜にするのではない。脚本は比喩の芯と山場の起伏を立て、筋を縛りにしない（筋を追うために絵を選ぶと、感動ではなくショボくなる。心が動く絵を先に置き、筋はそれを支える程度にする）。構成・演出とエフェクト・つなぎの担当の案と監督役の判定では、山場ごとに「観客は何を予測していて、それをどこでどう裏切るか」を書かせる。MV の定石（歌詞の場面を順に絵にする・サビで明るく広くする・最後は夜明け・人と AI を鏡で対にする など）は、定石と自覚したうえで裏切れる所を探させる。よく見る手の組み合わせだけの中庸な案は、決まりに触れなくても「直す」に入れる（本人の言葉 2026-10-12:「ストーリーを追従しようとしすぎて縛りにならないようにしたい。そうすると感動ではなくショボくなりがちである。感動を与えるため、中庸ではないブレイクスルーを常に意識してほしいし、感動は予測できない意外性が重要である、なのでエキセントリックな感じを目指す（人が思いつかない演出）がそこには必要」「脚本がエキセントリックというよりは、その中の構成や演出やエフェクトのレベルで組み入れて欲しいということだかね。」）
- **感動のもう 1 つの柱はカタルシス（溜めた緊張が解き放たれる解放）**。意外性だけで解放の無い山は驚いても冷め、解放だけで意外性の無い山は平凡になる。脚本で「何を溜めるか（抑え・葛藤・我慢・欠け）と、どこで解き放つか」の起伏を立て、構成・演出・エフェクトで溜めの長さと静けさ、解放の大きさと速さを作る。解放は溜めた分だけ効くので、溜めを削らない。担当の案と監督役の判定では、山場ごとに意外性と並べて「何を溜めて、どの秒で解き放つか・溜めに見合う解放か」を書かせる（本人の言葉 2026-10-12:「『感動』だけど、意外性も重要だけど、カタルシスも大事だからね。」）
- **1 分以上の作品は、全編を先に作ってから細部を直す**。全編の絵コンテ（担当と監督役で 1 回）→ AI 素材をまとめて頼む（本人の手作業の Midjourney は 2〜3 便）→ 届いた順に全編の粗い通し → 本人の通しの視聴 → 細部、の順にする。区間の作り込み（px・コマの値・点検の数）と見せ場の全部の層は粗い通しの後に回し、先に始めた区間の直しは ROADMAP に積んで止める。判定と担当の案のたびに「これは全編の粗い通しの前に要るか」を問わせる。山の効き目は前後の流れの中でしか決まらない（15本目は 0:36〜1:04 の 28 秒に判定 5 回・3 日かけ、全編の絵がほとんど無かった。切り替えた後は全編の絵コンテから Midjourney の文の確定まで 1 日で通った。本人の言葉 2026-10-17:「一回全部作ってから細部を直した方がいいんじゃない？脚本構成演出もあるんだし。じゃないといつ終わるかわからん。」）
- 生成 AI（画像・音楽・動画）の費用は企画で見積もり、承認を得てから使う。無料枠は無い
- 教材・解説は演出より内容の正確さを優先し、出典を `brief.md` に残す
- 共通部品（`engine/`）は2作品目で必要になったものだけ増やす。増やしたら全作品で出力照合を通す

## 監督役

演出の合否を決める役。制作担当（自分）とは別に、判定のたびに新しい独立エージェントを立てる（Agent ツールの `Plan` 型。読むだけで、ファイルは直さない）。前の判定を知らない目で見させるため、使い回さない。

- 渡すもの: 本人の依頼の言葉（要約しない）、`brief.md`、その段階で見ること（下の表）、材料の画像のパス（Read で見るよう指示する）、前の判定の指摘と直したこと
- 求める出力: **山場ごとの「心が動くか」の判定（いちばん先に）**と、その中身として**カタルシス**（何を溜めて、どこで解き放つか・溜めに見合う解放か）と**意外性**（観客の予測をどこで裏切るか。定石のままの山は名指しする。`docs/catalog/README.md` の本人の不評の手・見慣れた手と照らす）、合否、所見、修正リスト（秒・場面・直し方）、担当の案のどれを採り、どれを採らないかと理由、**次の局面で立てる担当と各担当への問い**。修正リストは「ここで直す」と「後の段階へ回す」に分けさせる。忖度させない。見落とし・代理の数字を信じていないか・制作担当が自分に甘い所も見させる。「無難に通す」判定に流れていないか（山が立っているか・筋に縛られて絵が説明になっていないか）も見させる
- 担当を束ねる（オーガナイズする）のは監督役。担当の報告の全文を読ませ、ぶつかる案は平均せずに 1 つを選ばせる
- 数値（明るさ・動きの量・同期のずれ）は代理の指標として渡す。合否は監督がコマを見て決め、最後は本人の視聴で決まる。監督の合格は本人の視聴の代わりにならない
- 材料は 1 つの書き出しからそろえ、比べる元は本人が見た版（前の本番）から同じ物差しで取る。試し書き出しの数字を本番の数字と比べない。代理の数字は決めた区間で切らず、ショットの終わりまで取る（13本目では、版の混ざり・試し書き出しとの比べ・短く切った区間を判定のたびに指摘された）
- 同じ項目が 2 回落ちたら、直し続けるか方針を変えるかを監督に決めさせる。課金が要る案（AI 素材の作り直しなど）になった時だけ本人に聞く
- 結果は `brief.md` の「監督役の判定の記録」に表で残す（見本: `works/circle-never-closes/brief.md` の 3 節）

| 判定 | いつ | 主な材料 | 見ること |
| :-- | :-- | :-- | :-- |
| 計画 | 台本と絵コンテを書いた後 | `brief.md`・`story.json` | **どの秒で心が動く設計か・何を溜めてどこで解き放つか・観客の予測をどこで裏切るか**、比喩や話の芯（縛りになっていないか）、観客に残す絵、見せ場が最大の音や話の山にあるか、単調な区間 |
| 素材 | AI 素材の指示文を渡す前・届いた素材を採る前 | 指示文・届いた絵の一覧（黒帯などの線つき）・原寸の切り出し・埋め込みの指示文と参照 | **その素材で山の心が動くか**、前後 20 秒の絵との並び、決まり（形・向き）、コードで直せるか、作り直すか、**人物の安全**（未成年に見える人物・肌の出た姿・性的に読まれうる姿勢・子に視線を集める構図。当たれば採らない） |
| 粗い通し | 絵の切り替えだけの試し書き出し | 場面ごとの一覧画像・色の帯・山場の前後のコマ列 | **山場ごとに心が動くか・どこで冷めるか**、絵の並びと起伏、続きすぎる絵、崩れ |
| 見せ場 | 見せ場を全部の層で作った区間の書き出し（`render.mjs --frames`） | 当たりの前後 ±12 コマを 1 コマずつ・伴奏の音量の曲線 | **決めの瞬間で心が動くか**、その大きさ・速さ・色 |
| 通し | 文字と効果を入れた全編の試し書き出し | `out/preview-sheet.png`・言葉や効果が出るコマ | **通しで心が動くか・山が回を追って育つか・どこで冷めるか**、文字が読めるか、層の重なり、くどい所 |
| 本番の前 | `/refine` の後 | 冒頭 3 秒・最後 10 秒・サムネイル候補 | **冒頭で引き込まれるか・最後に余韻が残るか**、音なしで成立するか、サムネイル候補の人物の安全（素材の行と同じ） |

- 尺で回数を変える。1 分未満は「計画」と「通し」の 2 回（通しで本番の前も見る）。1 分以上は 5 段階すべて
- 材料の作り方の見本は `works/circle-never-closes/scripts/`（`review.py` は色の帯・動きと伴奏の図・幕ごとの一覧、`hit_sheet.py` は当たりの前後、`cue_sheet.py` は言葉が出るコマ）。作品にコピーして使い、2 作品目で使ったら `tools/` へ上げる。1 コマ単位で抜くときは ffmpeg の `select=eq(n,N)`（`-ss` は数コマずれる）

## 担当（案を広げる・専門の目で見る）

監督役のほかに、案を広げて専門の目で質を上げる担当を 4 つ置く（本人の決定。2026-10-07）。どれも局面ごとに新しく立てる独立エージェント（`Plan` 型・読むだけ）で、出すのは案と評価だけ。**担当は本人に言われなくても、下の局面のたびに立てる。束ねる（オーガナイズする）のは監督役**（本人の言葉 2026-10-10:「スキルで定義した各役割の担当者は局面局面でちゃんと提案および評価をしてくださいね」「各役割の担当者は私が言わなくてもスキルとしてちゃんと出てくるようにしてね。ただし、それをオーガナイズするのは監督」）。**採る・採らないは監督役が決める**（担当どうしの意見がぶつかっても平均しない。選んだ理由を `brief.md` の判定の記録に残す）。

担当の評価も、**最初に山場ごとの「心が動くか」**（動く／動かない・どの秒の何の対比で・動かないならなぜ）を書かせ、下の表の専門の点検はその後に書かせる。

| 担当 | 案で出すもの | 評価で見ること |
| :-- | :-- | :-- |
| 脚本 | 比喩の芯・話の流れ（縛りにしない）・溜めと解放の起伏（カタルシス）・観客に残す絵・言葉の芯・演出の余白（構成・演出が意外な見せ方を差し込める区間） | 計画を知らない観客として見て、心が動くか・溜めた分が解き放たれるか。筋が縛りになって絵が説明になっていないか。素材や案が話の芯の何を語るか |
| 構成・演出 | 幕の割りと起伏（6 つの差）・見せ場と溜め（溜めの長さと解放の大きさ＝カタルシス）・変化球の差し方・テンポ・対比（静と動など）・**意外性の一撃**（観客の予測を裏切る、人が思いつかない見せ方） | 起伏、単調な区間、続きすぎる絵に加えて、**もう一段良くする案**（見せ方・間・カメラ・層の重ね・色の切り替え）を、効く順に秒つきで。素材は前後 20 秒の絵との並びで |
| 字幕・文字 | どの語を中央に大きく出すか（MV では本人が先に指定するので、指定を待って置き場所と出し方を出す。本人の言葉 2026-10-12「字幕で強調する部分は私が先に伝える。」）・どの行を下の字幕にするか・文字だけで見せる場面・書体と出し方（多彩に） | 読めるか（縦のスマホ幅も）、歌や声との時刻、強調の過不足、同じ出し方が続いて埋もれていないか |
| エフェクト・つなぎ | 見せ場と要の語の効果、つなぎ（切り替え・重ね替え）、AI 動画の調子、届いた素材のコードでの直し、**人が思いつかない効果とつなぎ**（定石の効果を裏切る形）、**山場ごとの Remotion の部品の候補**（下の決まり） | 安っぽさ・不自然さ・弱さ・くどさ・よく見る手のままの所と直し方 |

立てる局面（既定は 4 人全員。監督役が前の判定の「次の局面で立てる担当と問い」で顔ぶれや問いを変えたら、それに従う）:

| 局面 | 担当に出させるもの |
| :-- | :-- |
| 企画（確認1の前） | 方向の違う案を 2〜3 ずつ |
| 台本と絵コンテ（「計画」の判定の前） | 絵コンテへの案（構成・言葉の出し方・効果とつなぎ） |
| AI 素材の指示文を渡す前（本人の手作業の Midjourney も） | 構図・角度・大きさ、コードで重ねる物の空け方、頼まずに済む絵（14本目で、MJ に構図を頼む段で担当を立てたら、真上の構図と 7 機をコードにする案が採られた） |
| 届いた素材を採る前 | 素材の評価（採る・直して採る・作り直す）と、その素材を生かす案 |
| 粗い通し・見せ場・通し | 評価と、もう一段良くする案 |
| 本人が演出の案や指摘を出したとき（手直しを含む） | 本人の案の評価（採る・変えて採る・採らない）と、案や指摘の奥にある「もっと良くしたい」に届く案（指摘されていない所も含めて） |

- 監督役が束ねる: 判定の出力の最後に「次の局面で立てる担当と、各担当への問い」を書かせる。制作担当はそのとおりに立て、担当の報告の全文をファイルに残して次の判定の材料に添える。担当を減らすのも監督役が決める（制作担当が手間を理由に減らさない）
- 案は発散させる。担当には無難な 1 案ではなく、互いに方向の違う案を 2〜3 出させ、監督役に組み合わせを選ばせる。案ごとに効き目（どこで何の対比で心が動くか）と手間（コードだけか・素材の作り直しや課金が要るか）を書かせる。構成・演出とエフェクト・つなぎの案には **意外性の一撃**（どの秒で・観客が何を予測していて・どう裏切るか）も書かせ、少なくとも 1 案は振り切ったエキセントリックな案にさせる（手堅い案と混ぜてよい）
- 渡すもの: 監督役と同じもの（本人の依頼の言葉・`brief.md`・その局面の材料）と、本人の好み。好みは要約して渡さず、memory のファイル（`C:\Users\Masashi.Onda\.claude\projects\c--work-lite-movie-creator\memory\` の `user-*`・`mv-*`・`midjourney-*`・`check-highlight-impact`）を直接 Read させる（要約すると書き落とす。13本目の試しで「要所の言葉だけを大きく出す」を落とし、脚本の担当がその好みと逆の案を出した）
- 構成・演出、字幕・文字、エフェクト・つなぎの担当には、案を出す前に演出の見本帳 `docs/catalog/README.md` を Read させ、案に関わるカテゴリの節を本体（`own.md`・`film.md`・`motion.md`・`remotion.md`）から読ませる。カタログから選ぶだけの案は出させず、案ごとに「カタログのどの手を裏切るか・どれとどれを意外な形で組むか」を書かせる。本人が不評と言った手に当たる案は、今回なぜ違うかを書かせる。外部の手を新しい手として出す前に、README の「外部の手のうち自作で使ったもの」と照らさせる（本人の言葉 2026-10-13:「カタログみたいなものを持っておいた方が作成時の選択肢が広がるのではないか？」）
- **Remotion の部品の候補をできるだけ出させる**。エフェクト・つなぎの担当には局面のたびに、山場ごとに `docs/catalog/remotion.md` の公式部品（@remotion/effects の 73 種・transitions・light-leaks・motion-blur・noise・paths など）と外部の道具から候補を 1〜2 つ書かせる。構成・演出と字幕・文字の担当にも、効く所があれば出させる。候補ごとに、どの秒のどの層に何をどう掛けるか・導入済みか（未導入なら npm で足す手間と、全作品の出力照合が要ること）・Chrome のフラグが要るか・見慣れた手か（README の本人の不評の手と旭日の決まりに触れないか）を書かせる。採る・採らないは監督役が決め、採らなかった候補も理由を判定の記録に残す。試しを Python などで作る段でも、本番で Remotion の部品に置き換えられる効果（ぼかし・揺れ・色・つなぎ）は候補として挙げさせる（15本目では、担当も監督も見本帳の Remotion の節を一度も引かず、白の試しのぼかし・揺れ・色の刷り替えを全部 Python で自作していた。本人の言葉 2026-10-15「今後はremotionの候補案を極力出させるようにして。スキルにもぜひ書いてください。」）
- 同じ局面の担当は同時に立てる。材料は監督役と共通にし、担当ごとに作らない（局面の材料を 1 つのメモにまとめ、本人の言葉は原文で入れる）
- 監督役は合否を決める守りの役、担当は質を上げる攻めの役（本人の言葉「演出担当は質を上げる部分でも活躍してほしい」）。担当には、崩れや決まりの違反だけでなく「通ってはいるが、もっと良くなる所」を探させる。決まりに触れる案は捨てさせず、触れない形に変えて出させる
- 尺で減らす。1 分未満の作品は、脚本と構成・演出を 1 人に、字幕・文字とエフェクト・つなぎを 1 人にまとめる。声の作品（童話・解説）では、字幕・文字の担当が台詞の字幕も見る

## 流れ

### 1. 依頼を読み取り、作品名を決める

題材・目的・見る人・尺・画面の向きを読み取る。作品名（slug）は英小文字・数字・ハイフンで、`works/` の既存の名前と重ならないものにする。

### 2. 企画 → 確認1

1. 題材が本人や本人のプロダクト、実在の事業なら、題材側の最新の正本（対外文言・改修履歴・画像の決まり）を先に読み、制約を `brief.md` に書く（7本目で LP だけ見て企画し、作り直した）
2. `docs/genres.md` から近いジャンルの定石を選び、テイスト（絵柄・配色・フォント・音）と技術（コード描画・シェーダー・AI 画像・AI 音楽・声・AI 動画）を決める
3. 担当は脚本から立てる。脚本の担当に方向の違う脚本を 2〜3 案出させ、監督役に講評と推奨を付けさせて、**本人が確認1で脚本を選ぶ**。推奨以外の案も、単体で読んで情景が浮かぶ完成した形で見せる。脚本が決まってから構成・演出の担当、その後に字幕・文字とエフェクト・つなぎの担当（この 2 人は同時でよい）を立てる。確認1は、脚本の選択と、演出・技術・費用の承認の 2 回に分けてよい（本人の言葉 2026-10-07「ふつうは脚本がきまってから演出だと思うが」・2026-10-12「脚本は私が最終的に選ぶ。」）
4. 費用を見積もる。作り直しの分として、生成する数の 1.5 倍で計算する（例: 画像 6 枚 × 1.5 × 0.101 ドル ＋ 曲 2 本 × 0.04 ドル ＋ 声）。単価は `docs/genres.md` の表を使う
5. AskUserQuestion で確認する
   - 質問文に、なぜ今聞くのかと企画の要約（目的・尺・向き・テイスト・技術・費用）を入れる。この後は絵コンテも途中の判定も監督役の OK で進め、次に本人に見せるのは完成動画だと書く
   - 選択肢は「この企画で進める（推奨）」と、代わりの案を2つ（例: テイスト違い、費用を抑える案）。各案の description に、何が変わるかと費用を書く
   - 作り方で見た目と費用が大きく分かれるジャンル（クレイアニメなど）は、作り方の案（コード描画／AI 画像／AI 動画）を並べる。題材も決まっていなければ、題材の案を2問目にして同じ AskUserQuestion で聞く（確認の回数を増やさない）
6. 承認されたら `node tools/new-work.mjs <作品名> --title "題名"` で雛形を作り、`brief.md` の企画の表を埋める

### 3. 台本と絵コンテ → 監督役の「計画」の判定

1. `story.json` に台本を書く。場面 → 文、話し手ごとの演技指示（`styles`）。読み聞かせ調なら1秒あたり約 4.5 字（1本目の実測）で尺を見積もる
2. `brief.md` の絵コンテ表に、場面ごとの台詞・絵と動き・素材（AI で作るなら指示の要点）を書く
   - 声の無い、曲に合わせる作品は、台本の代わりに区間ごとの絵コンテと曲の指示を書く。秒数は目安で、曲を作ってから解析して区切りを決め直すと書いておく（`docs/genres.md` のアートの節）
   - 担当（企画の監督役が指示した顔ぶれ。指示が無ければ 4 人）を同時に立て、絵コンテに構成、言葉の出し方（中央に大きく出す語・下の字幕・文字だけの場面・書体と出し方）、見せ場の効果・つなぎの案を出させる。採った案を絵コンテに書き、採らなかった案は監督役の判定の材料に添える
3. 監督役に「計画」を判定させる。「直してから進める」なら直して、新しい監督役にもう一度判定させる。Plan Mode で計画を出すときも、ExitPlanMode の前に監督役の OK を取る（12本目では、初版の計画を本人が「監督エージェントがメタ認知的に OK であればよい」と差し戻した）
4. **ここから先は、下の「止める条件」に当たらない限り、最後まで止まらずに作る**

### 4. 素材を作る

- 声: `uv run --script tools/tts.py <作品名>`。1秒あたりの字数が 3〜6 字から外れる文は、読み間違いか間の取り方がおかしいので聞き直す（台詞を変えて、その文だけ作り直す）
- AI 画像: `story.json` の `images` に指示を書き、`uv run --script tools/image.py <作品名> --yes`（`--yes` は確認1で費用の承認を得たときだけ付ける。付けないと件数と費用の目安を表示して止まる）。商品や人物の見た目をそろえるときは、先に基準画像を1枚作り、各画像の `refs` に指定する
- AI の曲: `story.json` の `music` に指示を書き、`uv run --script tools/music.py <作品名> --yes`。歌を入れないときは「Instrumental only, no vocals.」と書く
  - 曲に合わせる作品は、届いた曲をすぐ解析して、区切りを拍の番号で決める（見本: `works/cosmic-pulse/scripts/analyze_audio.py`）。Lyria は区間の秒数やテンポの指示をおおよそしか守らない。区切りの拍の決め方は `docs/engine.md` の点検項目 11
- AI 動画（Veo）: `uv run --script tools/video.py <作品名> --yes`。流れは `docs/genres.md` のクレイアニメとアニメの節
  - 各カットの最初のコマを AI 画像で作る（主役は基準画像を `refs` で参照）。`story.json` の `videos` に動きの指示を英語で書く。動きは 1 カットに 1〜2 個
  - **まず 1 カットだけ作り**（`--only <id>`）、見た目と動きを確かめてから残りを作る（残りは同時に依頼されるので、待ち時間は約 40 秒）。`--yes` は画像と同じく、承認済みのときだけ付ける
  - 動画の中の出来事（ぶつかる・光る）に演出を合わせるときは、各コマの明るさ（`ffmpeg -i public/video/<id>.mp4 -vf "signalstats,metadata=print:key=lavfi.signalstats.YAVG" -f null -`）でコマ番号を測る
  - 届いた動画は、0.5 秒おきのコマを並べた一覧画像（`ffmpeg -i raw/<id>.mp4 -vf "fps=2,scale=640:-1,tile=4x3" -frames:v 1 out/<id>-sheet.png`）を Read で見て、崩れ（顔が変わる・物が消える）を探す
  - 崩れた区間は、作り直すより切り落とす方が安い。区間の境目は偶数のコマにする（2 コマずつ同じ絵にする加工とずれないように）。目を開けるなど顔を作り直しやすい動きは、最後のコマも画像で渡す（Lite では 8 秒のときだけ通る）
  - **Veo で外れた本・品質を上げたい本は、ほかのモデル（Kling・Seedance など）を fal 経由で試す**（本人の決定 2026-10-11）。fal は各社の動画モデルを 1 秒いくらの従量で呼べる仲介の API で、キーはユーザー環境変数 `FAL_KEY`。各社の公式のプランやクレジットは買わない。`story.json` の items に `"model"` で fal のモデル名を書き、Veo と同じ最初のコマと文で id を替えて作る（例 `p04k`。`tools/video.py` が fal へ送り、二重課金の歯止め・原本の保存・加工は Veo と同じ）。使えるモデルと 1 秒の単価は `tools/video.py` の `FAL` と `docs/genres.md` の表。試す目安は、同じ外れ（頼んでいない動き・止まるはずの物の滑り・目や顔の描き直し）が Veo の作り直しで 2 回続いた本と、山場で Veo の質が足りない本。費用は承認の内で見積もりに入れ（Kling は Veo Lite の約 2 倍、Seedance は約 5〜6 倍）、試した結果（Veo との比べ）を `docs/genres.md` に残す
- 生成した画像と動画は Read で目で確かめてから場面に使う。使った指示は `brief.md` の「AI 生成物の使用箇所」に記録する
- **人物は大人にする**。AI 画像と MJ の文に girl・kid・child を書かず、除外の語（MJ は --no）に child, teen を入れ、服は肌の出ない物を語で指定する（座る姿が要らなければ sitting も除く）。届いた絵の人物は原寸で、未成年に見えないか・肌の出た姿や性的に読まれうる姿勢でないかを見て、当たれば採らない。編集で隠すときは、隠した後の形が別の読みにならないかも見る（15本目で MJ の `LARGE "SURE" on girl` が、下着のような服で膝を抱える幼い子を描いた。担当と監督は「啓発に読まれる」とまでしか言わず、下着に見える色を編集で肌に替えて悪くし、サムネイル候補にまでした。本人の言葉 2026-10-15「SUREの少女の画像だが卑猥じゃないかな？」）
- AI 素材（本人の手作業の Midjourney も）は、指示文を渡す前と、届いた素材を採る前に、担当と監督役を立てる（監督役の「素材」の判定）。届いた絵は判定の前に、埋め込みの指示文と参照（`tools/import_mj.py` が出す）を照らし、黒帯などの線を引いた一覧と原寸の切り出しを材料にする
- 文の途中の語に演出を合わせるときは、無音区間を測って秒数を定数にする（`docs/engine.md` の「場面の作り方の要点」）

### 5. 場面を作る

- 雛形の `src/Main.tsx` の `SCENE_VIEWS` に場面を登録し、場面の絵は `src/scenes/` に作る
- 共通部品（`Stage`・`makeAnim`・`Se`・`Voice`・`Captions` など）は `src/engine.ts` から読む
- 他の作品の部品を使いたいときは、この作品にコピーして使う（2作品目で使うものは、engine へ上げるかを検討する）
- 声を使わない作品は `src/timeline.ts` で尺を固定する。AI 動画を並べる作品は、使う区間（元の動画のコマ番号）を並べ、`@remotion/media` の `<Video trimBefore>` で見せる（見本: `works/night-cat-clay/src/timeline.ts`・`Main.tsx`）
- `npm run typecheck` を通す
- 1 分以上の作品は、絵の切り替えだけができた段階で試し書き出しをして、監督役に「粗い通し」を判定させる（担当の評価と案を同時に取り、添える）。文字と効果はその後に足す。見せ場は、本人が全編の粗い通しを見た後に、全部の層をそろえて `--frames` の区間書き出しで作り、「見せ場」を判定させる（同じく担当を添える。全編の通しより先に区間を作り込まない。原則の「全編を先に作ってから細部を直す」。0.13.0 までは「見せ場は全編を待たず先に作る」だったが、15本目でこれが 28 秒に 3 日の詰まりを生んだので逆にした）

### 6. 試し書き出しで点検する

1. `node tools/render.mjs <作品名> --preview` を実行し、`out/preview-sheet.png` を Read で見る
2. `docs/engine.md` の「試し書き出しで点検すること」を全項目確かめる。気になるコマは ffmpeg で抜き出して拡大して見る
3. 直したら試し書き出しをやり直す。3回直しても残る問題は、報告に書いて先へ進む
4. 見つけたことと直したことを `brief.md` の「点検の記録」に書く。自分の点検が済んだら、監督役に「通し」を判定させる（担当の評価と案を添える）
5. 音に合わせる作品は、試し書き出しの mp4 で光と音のずれを測る（見本: `works/cosmic-pulse/scripts/check_sync.py`。書き出した mp4 の音は 42.7ms 遅れる）
6. **本番の書き出しの前に `/refine`（コードの手直しと正確性の点検）を済ませる**。点検で直したら 1〜3 をやり直す（8本目では本番の後に点検し、見た目の欠陥が 4 件見つかって本番を 4 回書き出し直した。4本目でも一覧画像で見落とした部品の欠けを点検が見つけた）。その後で監督役の「本番の前」の判定を取る

### 7. 本番の書き出し

`node tools/render.mjs <作品名> --loudness -16` をバックグラウンドで実行する（1920×1080・2分で約 25 分、20 秒の CM で約 4 分）。`--loudness` は書き出した後に音量をそろえる。終わったら表示されるラウドネス（-16 LUFS 前後）と最大音量（-1 dB 未満）を確かめる。

書き出しが予定の倍を過ぎても終わらないときは、一時フォルダ（`%TEMP%` の `react-motion-render*`）のコマの画像の数と時刻で、止まったコマを探す。13本目では、同じ動画を 1 コマに 3 回描いた所で 35 分止まり、Remotion の待ち時間の打ち切りも効かなかった（避け方は `docs/engine.md` の「場面の作り方の要点」）。

### 8. 記録して報告する

- `brief.md` の実績（長さ・費用・書き出しの所要時間）を埋める
- 報告には、完成動画のパス・長さ・費用・点検で確かめたこと・確かめられていないことを書く。冒頭の 2〜3 行で、何を AI に作らせ何をコードで作ったか（作り方）と、どのコマを見て何を測ったか（確かめ方）を先に書く。監督役の判定の回数と、演出を変えた主な指摘も 1〜2 行で書く。最終判定はユーザーの視聴であることを明記する
- プロジェクトの `improvement_list/` に作品の記録（対象・変更内容・理由・分かったこと）を書き、`ROADMAP.md` の完了欄にリンクを足す。点検で残した指摘は ROADMAP の未対応タスクに積む。ジャンルの定石として使える知見は `docs/genres.md` に、点検で見つけた新しい失敗は `docs/engine.md` の点検項目に足す。作品で新しく使った手は `docs/catalog/own.md` の該当カテゴリに 1 行ずつ足す

## 止める条件（確認1のあとでも止めてユーザーに聞く）

- 見積もりを超える費用が要る（作り直しが増えたなど）
- API の失敗（課金・権限・提供終了）で素材が作れない
- `engine/` の変更で、既存作品の出力照合（`tools/golden.mjs <作品名> check`）が通らない
- 教材の内容の事実関係に確信が持てない

## 既存作品を直すとき

1. その作品の `brief.md` と `story.json` を読んでから直す。本人の視聴の指摘は `works/<作品名>/viewing-<n>.md` に原文のまま書き、制作担当の読み（どの秒の、どの層＝絵・効果・字の、何を・要る物）を表にする。指す層は本人の秒のコマを抜き出して決める（13本目で「エフェクトがしょぼい」を字幕と読みかけ、本人の補足で画面中央の光と分かった）。本人の今の言葉は過去の監督の決まりより優先し、作品の芯（比喩・残す絵）を壊さない線を監督役に引かせる
2. 前の版を残す。完成直後の手直しは同じフォルダで直し、前の完成動画を `out/<作品名>-v<n>.mp4` に移してから書き出す。場面の追加など中身を大きく変えるときは `works/<作品名>-v2` にコピーして直す。どちらにするかは確認で選んでもらい、作品フォルダを git に入れていないと前の版のコードは残らない（動画だけ残る）ことを選択肢に書く
3. 声は作り直さない。`tts.py <作品名> --offline` で、作り直しが要る文が無いことを確かめる。台詞を変えるときはその文だけ作り直し、その文に合わせた演出の秒数を測り直す
4. 直したら 6（試し書き出しの点検と `/refine`）→ 7（本番の書き出し）。本番の前に、直した版を監督役に判定させる（12本目の手直しでは、本人の 17 点の指摘を入れた版に、監督が指摘 1 点と推奨 3 点を出した）。本人の問い（例: 書体をどうするか）にも、答える前に監督役に判定させてよい。直した内容は `brief.md` の点検の記録と `improvement_list/` に書き足し、本人の視聴の反応は `docs/catalog/own.md` の反応の欄（不評なら README の「本人が不評と言った手」にも）に写す
5. 指摘が多い手直し（10 項目前後）は、監督役の判定を 3 回にする: 直す前に `viewing-<n>.md` と直し方の計画（決まりを変える所を表にして）、直した後に見せ場と通しをまとめて、`/refine` の後に本番の前（13本目の 17 項目はこの 3 回で通した）。本番の前の材料は本番の候補（7 の書き出し）から作ってよく、合格ならそのまま本番にする（全編の原寸の書き出しが 1 回減る）。監督役には「本人の視聴の前に伝えること」（本人の言葉どおりにしなかった所・読みで決めた大きさや色・直さなかった所と理由）も出させ、報告に書く。直し方の計画の段でも担当（既定は 4 人）を立て、本人の指摘を言葉どおりに直すだけでなく、指摘の奥にある「もっと良くしたい」に届く案（指摘されていない所も含めて）を出させる。本人が制作の途中で演出の案を出したときも同じ（14本目で本人が出した実写の寄り 4 案と文字だけの場面は、4 人と監督役で採否を決めた）
