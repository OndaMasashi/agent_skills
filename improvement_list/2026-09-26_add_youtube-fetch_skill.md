# youtube-fetch スキルの追加（YouTube の情報取得の手順を統一）

## 対象

- `youtube-fetch/SKILL.md`（新規）
- `youtube-fetch/scripts/fetch_youtube.py`（新規）
- `youtube-fetch/references/visual.md`（新規）
- `tapestry/SKILL.md`（YouTube の取得部分を youtube-fetch へ委ねる形に変更）
- カタログ 4 箇所（`skill_catalog.md` / `generate_skill_catalog.js`（v18 のまま再生成）/
  `~/.claude/skills-catalog.md` / `~/.agent/skills-catalog.md`）
- `skills-main/CLAUDE.md`（カテゴリ一覧に追加、カタログの版を v15 → v18 の実態に合わせた）

## 変更内容

- `fetch_youtube.py`: URL を受け取り、題名・チャンネル・公開日・長さ・概要欄・チャプター・時刻つき字幕を
  `<動画ID>.md` 1 枚に書き出す。主経路は yt-dlp、失敗時は youtube-transcript-api へ自動で切り替える。
  依存は PEP 723 で宣言し `uv run --script` で実行する（毎回の pip インストールをやめる）
- 字幕は「話されている言語の手動 → 同じ言語の自動（`-orig`）→ ja/en の手動 → その他の手動 → 自動翻訳」の順に選ぶ。
  自動字幕に誤判定の `en-US-orig` と正しい `ja-orig` が同居する動画があったため、`info["language"]` で選ぶ
- 字幕は 30 秒ごとの段落にまとめ、チャプターの位置に見出しを入れる（37 分の動画で 1,023 行 → 322 段落）
- `visual.md`: 映像を確かめるときの動画取得（480p 全体）・一覧画像・場面の切り替わり検出の手順。
  区間指定の取得（`--download-sections`）が 480p・4 秒で 400 秒を超えても終わらなかったため、`timeout` を必須にした

## 理由

YouTube の情報取得の手順が毎回違っていた（2026-09-26 時点で 3 通り）。

- ai-avator: 作業フォルダへ yt-dlp を pip で入れ、VTT 字幕を自作スクリプトで文字化
- works-gallery のセッション: youtube-transcript-api を仮想環境に入れて取得
- tapestry: VTT を取るだけの 1 行（文字化なし）

どれも記録が残らず、次のセッションで一から探し直していた。

## 確認したこと

- 日本語の自動字幕（37 分）・英語の手動字幕・ai-avator の動画（14 分）の 3 本で取得できた。
  ai-avator で当時取った字幕と文字数がほぼ一致（5,312 / 5,300 字）
- 予備の経路へ強制的に切り替えても同じ 1,023 行が取れた
- 存在しない ID は exit 1、字幕なし（部品を差し替えて再現）は exit 2
- 初回 77 秒（依存の取得）、2 回目以降は約 8 秒
- /refine（code-simplifier）で整理した後も、出力が整理前と 1 文字も変わらないことを確認

## 点検の指摘への対応（同日）

/code-review と security-reviewer の「通常」の指摘 5 項目を、ユーザーの判断で直した。

- 字幕の取得が空・失敗で終わっても、取れた動画情報（概要欄・公開日・チャプター）を残し、字幕だけ予備の経路に取りにいく。
  通信に待ち時間の上限（30 秒）を付けた
- 字幕の種類を「手動／自動生成／自動翻訳」で書き分けた（自動翻訳は「話された言葉そのものではない」と明記）
- 概要欄は、中身に出てくる最長のバッククォートの連続より長い囲みで包む（囲みを抜けて見出しを偽造できない）
- 公開日は時刻から日本時間で出す（時刻が無いときだけ UTC の日付で、そう書く）
- 「字幕が無い」（終了コード 3）と「取得できなかった」（4）を分けた。yt-dlp の警告を集めて、
  PO token（YouTube が求める追加の認証）不足で字幕の一覧が欠けたときは「取得できなかった」にする。
  動画の形式が選べなくても動画情報と字幕は取る（`ignore_no_formats_error`）。
  この設定で存在しない動画も中身の空の情報が返るようになったので、長さも公開日も無ければ止める
- あわせて、様子見の指摘のうち同じ箇所で直せる 3 件も直した。引数の誤りを終了コード 2 に分けた（以前は「字幕が無い」と同じ 2 だった）。
  韓国語の字幕を空白でつなぐようにした。予備の経路で中身が空の字幕を取ったときは「取得できなかった」（4）にした

確かめたこと: 実物の動画で 6 通り（日本語の自動字幕・英語の手動字幕・予備の経路・存在しない ID・YouTube 以外の URL・誤ったオプション）、
部品を差し替えた試験で 22 項目（経路の組み合わせ 7 通り、PO token の警告、字幕の取得失敗で動画情報が残ること など）。
通常の経路の出力は、公開日に「（日本時間）」が付いた以外、直す前と同じ。

## 2 回目の点検で見つかった直し残し（同日）

上の修正をもう一度 /refine にかけたところ、「無い／取れなかった」の区別が実際には働いていないと分かった。

- PO token が足りずに字幕を捨てた知らせは、yt-dlp の標準の接続方式では**警告ではなく詳細ログ（debug）にしか出ない**
  （`_report_pot_subtitles_skipped`。利用者を混乱させないための作り）。警告だけを集めていたので、1 件も拾えていなかった。
  → `verbose: True` にして詳細ログを受け取り、「PO token」と「subtitle」を含む行だけを拾う
- 年齢制限の動画（実例 `Tq92D6wQ1mg`）は長さと公開日が取れるので、「字幕なし（3）」と誤って報告していた。
  → 字幕が 1 本も見つからないとき、形式の警告以外の警告（年齢確認など）か、`availability` がログイン必須なら「取れなかった（4）」にする。
  実物で 4 になることを確認した
- 予備の経路の「無い」で、yt-dlp の「取れなかった」を「無い」に書き換えていた（塞がれた結果かもしれないのに）。
  → 書き換えない。逆に、予備の経路が字幕を一覧に見つけて中身だけ取れなかったときは、「無い」を「取れなかった」にする
- 「待ち時間の上限を付けた」のに、予備の経路（youtube-transcript-api）には付いていなかった。
  → `http_client` に上限つきの通信部品を渡す
- 題名・チャンネル名・チャプター名に改行を仕込めば、偽の見出しを作れた（セキュリティ点検）。
  → 改行と制御文字を畳んでから書く。SKILL.md の「投稿者が書いたデータ」の対象にも加えた
- あわせて: 言語が `en-US` のように地域つきで来ると話し言葉の字幕を取り逃がしていたのを直した。言語が取れないとき、
  元の言語の自動字幕が 1 本だけならその言語とみなす。時刻の無い公開日の基準を「UTC」と断定していたのを
  「YouTube の日付。日本時間とは 1 日ずれることがある」に直した（yt-dlp は UTC か太平洋時間の日付を入れる）

確かめたこと: 部品を差し替えた試験 38 項目、実物の動画 5 通り（日本語・英語・年齢制限・存在しない ID・YouTube 以外の URL）。
日本語の動画の出力は、直す前と同じ。

## 残作業

点検の指摘のうち「様子見」のもの（2026-09-26 時点）:

- 予備の経路の字幕の選び方が主経路と違う（話されている言語を見ていない）。字幕を順位づけする処理が 2 か所にある
- 翻訳に使えない自動字幕（`-orig` が付かないもの。広東語など）を「自動翻訳」と表示する、または選べない
- `embed/videoseries` を動画 ID と誤認する。ID の右端に境界が無い（1 文字多く貼ると別の動画を取る）
- 最後の字幕より後に始まるチャプターの見出しが、字幕の節に出ない
- yt-dlp で動画情報が取れているときも、予備の経路が oEmbed を問い合わせる（使わない通信が 1 回増える）
- 終了コード 1 が、依存ライブラリの取得失敗・書き出しの失敗と区別できない（SKILL.md に注意書きだけ入れた）
- 3 回目の /refine はかけていない（2 回目の指摘への対応を、上の試験で確かめた）
